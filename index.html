Part 1 · VM deployment path

  • Built immutable backend and frontend AMIs with Packer so instances boot ready-to-serve, not self-configuring at launch.
  • Provisioned ASG, ALB, Route53 and ACM TLS in Terraform — the DNS, HTTPS and routing Kubernetes wires automatically.
  • Injected DB credentials at boot from Secrets Manager via an IAM instance role.
  • Parallelized AMI builds on a self-hosted GitLab runner, cutting build time roughly in half.

Part 2 · End-to-end alerting

  • AWS path: CloudWatch → SNS → Lambda posting to Slack in under 5 seconds.
  • Kubernetes path: Prometheus rules + Alertmanager routing, enriched with pod, namespace and reason.
  • Wrote three runbooks and an alert-vs-noise policy to prevent alert fatigue.
  • Fixed a secret-schema mismatch (dbname/username vs actual database/user) that silently broke every DB query.
◆ The diagnosis I'm most proud of

AWS alerts reached Slack; Kubernetes alerts fired but never arrived. I traced it past the config: Alertmanager showed context-deadline-exceeded timeouts; pods reached AWS services via VPC endpoints but timed out to every public IPv4 destination. The cluster was IPv6-only and Slack's API is IPv4-only, so delivery depended on a NAT64 gateway that wasn't functioning. The alerting was correct — the block was cluster-level egress infrastructure. That's the exact line between "my code" and "the platform," and naming it is what saves an on-call engineer hours.

AI-native workflow

Agent skills as infrastructure.

I treat AI as a force multiplier for real infra work — not a keyword. Do a task carefully once, then capture it as a reusable agent skill.

01

Capture, don't repeat

When a task is worth repeating — a deploy check, a review pass — I turn it into an agent skill so it runs consistently instead of from memory each time.

02

Plan-reviewed execution

I keep the model on a leash: plan first, review the plan against real state, then let it act. Judgment stays with me; the typing gets delegated.

03

Context as a file

Markdown context files keep an agent grounded in how a project actually works — the hard part isn't writing them, it's deciding what belongs in them.
