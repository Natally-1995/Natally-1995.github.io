01 — Experience

Where the numbers came from.

Two roles, five years, one throughline: replacing steps a human has to remember with steps a pipeline enforces.

Platform Engineer

Chowly · Chicago, IL · Nov 2023 — present

  • Wrote AI agents that read Terraform plans and flag risky IAM changes on pull requests. They comment; they can't apply or merge. Five of us use them. Terraform review went from 50 to 20 minutes.
  • Killed our SSH deploys. Now 8 services across 3 environments ship as immutable machine images. Deploys dropped from 30 to 8–10 min, rollbacks from 20–30 to 5–10, and we stopped taking downtime for them.
  • Wired the rest of it together so a merge builds the image and Terraform ships it. We rebuild monthly instead of patching by hand, which ended the drift problems we kept hitting.
  • Moved 20 services onto Argo CD. Nobody runs kubectl against prod anymore. We went from weekly releases to several a day, and merge-to-prod from 2–4 hrs to under 30 min.
  • Put tests, security scans, config validation and Terraform checks on 35 repos, so things break in review instead of in prod. Failed deploys went from 10% to under 3%.
  • Cut our AWS bill by about 18%, somewhere around $60–80K a year. Right-sized EC2 workloads, deleted what nobody was using, put lifecycle policies on storage, and added monitoring so it wouldn't creep back up.

DevOps Engineer

Grubhub, Inc. · Chicago, IL · Jul 2021 — Nov 2023

  • Wrote Terraform modules the team reused instead of clicking through the console or copying old configs. Standing up an environment went from days to hours.
  • Automated build, test and deploy for 10+ services with GitHub Actions and Jenkins. Took the manual steps out of our weekly release.
  • Built the Prometheus and Grafana dashboards and the alert rules behind them, for both the apps and the boxes they ran on. On-call started there.

02 — AI-native platform work

Agents with a leash.

I use AI as a force multiplier on real infrastructure, not as a keyword. The interesting part isn't that an agent can write Terraform — it's deciding exactly what it's allowed to touch.

AGENT 01

Terraform plan review

Reads a plan, flags destructive changes, replacements and blast radius before a human reads a line. Cut review from ~50 to ~20 minutes.

AGENT 02

IAM-risk PR review

Scans pull requests for permission changes — wildcards, privilege escalation paths, over-broad trust policies — and comments before merge.

AGENT 03

Runbook drafting

Turns a procedure done carefully once into a runbook that reads the same way every time, instead of living in one engineer's memory.

AGENT 04

Incident summaries

Assembles timeline, signals and impact from logs and alerts so the write-up starts from evidence rather than a blank page.

Built at Chowly and used by ~5 engineers. Scoped read-only with no apply or merge rights — judgment stays with the engineer, the typing gets delegated.
METHOD 01

Capture, don't repeat

When a task is worth doing twice — a deploy check, a review pass — it becomes a reusable agent skill so it runs consistently instead of from memory.

METHOD 02

Plan-reviewed execution

Plan first, review the plan against real state, then act. The gate is the whole design, not an afterthought bolted on later.

METHOD 03

Context as a file

Markdown context files keep an agent grounded in how a project actually works. The hard part isn't writing them — it's deciding what belongs in them.
